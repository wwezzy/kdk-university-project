Светлая и тёмная темы используют общие CSS-переменные. Выбор сохраняется в localStorage, поэтому после перехода на другую страницу он остаётся. ## Как работает Home

- HTML задаёт смысловую структуру: заголовок, основные действия, карточки, книги и FAQ.
- Карточки ведут на существующие страницы, а не на пустые ссылки.
- Сетка и адаптивные правила CSS меняют раскладку на узком экране.
- Использованы уже имеющиеся фото проекта; лишние демонстрационные виджеты прошлых заданий убраны.
- FAQ использует `details` и `summary`: раскрытие работает нативно, без лишнего JavaScript.

## Как работает About

- Страница объясняет концепцию университета, подход к обучению и показывает изображения кампуса.
- Отдельно указано, что это учебный проект, а не настоящий университет.
- Общие шапка, подвал, цвета и компоненты делают страницы визуально связанными.

## Переключение темы

1. При загрузке общий скрипт читает сохранённую настройку из localStorage.
2. У корневого элемента меняется атрибут `data-theme`.
3. CSS выбирает набор переменных для фона, текста, границ и акцентов.
4. Нажатие кнопки меняет тему и сохраняет настройку.
5. Следующая страница читает ту же настройку.

localStorage хранит строки и доступен в пределах одного origin. Это удобно для предпочтений, но не делает данные защищёнными. JSON позволяет сохранять и читать структурированные значения.

## API книг

- Тема выбирается из ограниченного списка, например `computer_science`.
- Запрос: `https://openlibrary.org/subjects/computer_science.json?limit=3`.
- `fetch()` возвращает Promise; `await` ждёт ответ, не блокируя весь интерфейс.
- Проверка `response.ok` отделяет успешный HTTP-ответ от ошибки.
- Ответ разбирается как JSON, из массива `works` выбираются названия, авторы и ссылки.
- Результат вставляется безопасными DOM-операциями с `textContent`, а не непроверенным HTML.
- На время запроса повторное нажатие отключается; статус сообщает о загрузке.
- Ошибка сети или некорректный ответ обрабатывается; есть кнопка повтора.
- Кэш уменьшает повторные запросы; сохранённые данные нельзя выдавать за только что полученные.

Названия DOM-элементов: `reading-subject`, `load-reading`, `reading-status`, `reading-results`, `reading-retry`. Найди соответствующую функцию в итоговом общем JS перед защитой: структура файлов могла измениться при интеграции.

## Возможные вопросы

**Почему без backend?**  
По заданию требуется frontend и симуляция авторизации через localStorage. Для настоящего сервиса нужна серверная часть.

**Можно ли хранить настоящие пароли таким способом?**  
Нет. Это только учебная симуляция с вымышленными данными. localStorage можно прочитать и изменить; он не заменяет защищённую серверную авторизацию.

**Как проверяли адаптивность?**  
Покажи фактически проверенные размеры и скриншоты из итогового отчёта. Не говори «на всех устройствах», если проверены только конкретные размеры.

**Что будет, если API не работает?**  
Будет сообщение об ошибке и повторная попытка; если есть ранее сохранённые результаты, интерфейс должен объяснить, что они из кэша. Остальные страницы остаются доступны.

**Зачем публичный API, если книги можно вписать в HTML?**  
API добавляет актуально запрашиваемые данные по выбранному предмету и демонстрирует асинхронную работу, состояния загрузки и обработку ошибок.

**Что лично сделал ты?**  
Назови свой реальный вклад: какие страницы собрал, какие решения выбрал, какой код изменил или проверил. Честно скажи, где использовал ИИ. Не приписывай себе работу коллег.
